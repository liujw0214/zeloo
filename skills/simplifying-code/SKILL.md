# 简化代码

## 原则

| 原则 | 规则 |
|------|------|
| **保持行为不变** | 输出必须与输入完全一致 |
| **显式优于巧妙** | 偏好显式变量而非嵌套表达式 |
| **简单优于整洁** | 偏好直接的代码而非模式化的「整洁」代码 |
| **精准修改** | 只修改需要简化的部分 |
| **暴露假设** | 修改前先识别导入者、依赖和测试覆盖 |

## 流程

1. **先读代码** — 修改前先理解完整文件和依赖
2. **识别不变项** — 公共API、返回类型、副作用、错误行为
3. **识别目标** — 找最高影响的简化机会
4. **按顺序应用** — 控制流 → 命名 → 重复 → 类型
5. **验证** — 测试通过、类型检查、无行为改变
6. **提交前审计** — 检查每行改动的必要性

## 常见问题与修复

| 问题 | 修复 |
|------|------|
| 深层嵌套（>2层） | 守卫子句提前返回 |
| 长函数（>20行） | 按职责提取为命名函数 |
| 参数过多（>3个） | 分组为选项/配置对象 |
| 重复代码（**3+**次） | 提取共享函数 |
| 魔法数字/字符串 | 命名常量 |
| 复杂条件 | 提取为描述性命名的布尔值或函数 |
| 死代码/不可达分支 | 完全删除 |
| 不必要的else | 移除else，缩进减少 |

## AI冗余清理

简化AI生成的代码时，特别针对：

- **冗余注释** — 删除复述代码的注释（`// 计数器+1` 在 `counter++` 上方）
- **不必要的防御性检查** — 删除上下文中不可能发生的条件判断
- **过度类型转换**（`as any`）— 修复实际类型或使用正确的泛型
- **过度抽象**（工厂模式产2个对象）— 内联代码
- **占位符桩**（`// ...`）— 保留原样
- **冗余错误包装** — 移除不必要try/catch
- **冗长的标准库重新实现** — 替换为标准库/框架的一行代码

## 停止条件

在以下情况停止并询问：

- 简化需要改变公共API
- 无法验证行为一致性
- 代码因领域原因故意复杂
- 范围暗示重新设计而非简化

## 约束

- 只简化请求的内容
- 不改变代码保持不变
- 不将无关的清理打包到一个补丁中
- 不引入框架级别的模式

## 验证

- 测试通过且类型检查通过
- 无行为改变
- 范围限于请求的文件
- 匹配测试范围到导入者数量

## 输出

简化后报告：

- **范围**：修改的文件和函数
- **主要简化**：改变了什么、为什么
- **验证**：测试通过、类型检查、无行为改变
- **剩余风险**：所做的假设、未触及的区域
