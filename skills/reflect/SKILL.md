# 反思

## 成功标准

- 每个错误/摩擦点引用具体时刻及其影响
- 改进是可操作的且有优先级的
- 每个技能审计提出可衡量的变更
- 询问用户哪些需要持久化到记忆
- 如有评审活动，回顾陷阱模式被捕获到持久记忆

## 流程

### 1. 会话回顾

扫描完整对话。对于每个发现，引用具体交流（引用或复述）及其影响。

| 类别 | 信号 |
|------|------|
| **错误** | 错误输出、错误假设、幻觉事实 |
| **摩擦** | 重复澄清、冗长响应、误读意图 |
| **浪费的努力** | 被丢弃的工作、先尝试的错误方法 |
| **胜利** | 值得重复的方法、顺畅的互动 |

### 2. 评审活动扫描（如有）

如会话包含PR或MR评审活动，在继续前运行此扫描。

**入站（我的代码被评审）：** 对于每个收到的评审评论：
- 我接受了吗？如果接受，评审者抓住了我错过的什么模式？这是反复出现的盲点吗？

**出站（我评审了别人代码）：** 对于我撰写的每个评论：
- 被接受了吗？
- 被拒绝但有有效反驳了吗？那是一个回顾陷阱。

### 3. 操作性学习

在列出改进前，扫描会话中值得保留的操作性见解。

应用5分钟过滤器：知道这个能节省5分钟以上吗？如果是，包含它。

### 4. 改进

**可衡量的具体改进**列表，按影响排序。每个项目一句话、命令式、可操作。最多10项。

通过AskUserQuestion询问用户："哪些我应该记住用于未来对话？"

将批准的项目保存到记忆文件。

### 5. 技能审计（如有技能使用）

对于会话中使用的每个技能：

**A. 自我检查门** — 如技能缺少成功标准+验证循环：
- 添加成功标准
- 添加自我检查部分

**B. Token效率** — 标记：冗长措辞、可合并部分、过大示例

**C. 其他** — 缺失边缘情况、模糊指令

**D. 指导不匹配** — 当技能被调用但其建议在此时被证明错误/过时/不适用

### 6. 捕获标记

**`remember:` 前缀**是最高置信度的捕获信号。当用户写以`remember:`开头的消息时，直接保存。

### 7. 模式检测

如出现2+个类似任务且无现有技能覆盖，建议新技能。

## 自我检查

在展示输出前，验证所有成功标准都满足。如有未满足，修订。
