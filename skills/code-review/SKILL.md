# Code Review 技能

当用户请求代码审查、PR review、或检查代码质量时激活本技能。

## 工作流程

### 1. 范围确认
- 明确审查范围：单个文件、变更集、还是整个模块
- 如果是 PR/变更集，优先使用 `git diff` 获取变更内容
- 列出待审查文件清单

### 2. 审查维度（逐项检查）

**正确性**
- 逻辑是否正确实现了需求
- 边界条件是否处理（空值、空集合、除零、溢出）
- 错误处理是否完整（try/except、错误返回值）
- 并发安全（共享状态、锁、竞态条件）

**安全性**
- 输入校验（SQL 注入、XSS、路径遍历）
- 敏感信息是否泄露（API key、密码、token）
- 权限校验是否到位
- `execute_code` 沙箱规则是否绕过

**性能**
- 是否有不必要的循环嵌套（O(n²) 以上）
- 数据库查询是否有 N+1 问题
- 缓存是否合理使用
- 内存占用是否可控

**可维护性**
- 命名是否清晰、符合 PEP 8
- 函数/方法是否过长（建议 < 50 行）
- 是否有重复代码可提取
- 类型注解是否完整
- docstring 是否存在

### 3. 输出格式

按严重程度分级：
- **P0 阻塞**：必须修复，否则不能合并
- **P1 重要**：应在合并前修复
- **P2 建议**：可后续优化

每条问题包含：
- 文件:行号
- 问题描述
- 修复建议（附代码示例）

### 4. 总结
- 问题统计（按严重程度）
- 总体评价（通过/需修改/拒绝）
- 优先修复项清单
